# 端点行为：收录与精选

## 1. `GET /collections/:id/topics.json` — 专辑阅读页

- query：`sort`（`added_at` / `topic_created_at` / `topic_bumped_at`，**默认 `added_at`**，非法值 400）+ `order`（`asc|desc`，**默认 `desc`** = 最新在前；`asc` 供按时间先后通读用）、分页。

- **三个排序键**：`added_at` = 收录时间（`collection_topics.created_at`）；`topic_created_at` = 话题创建时间（`topics.created_at`）；`topic_bumped_at` = 话题最新回复时间（`topics.bumped_at`，即核心话题列表的「最新活动」口径，非 `last_posted_at`）。三者皆非空，无空值排序规则；**并列时以 `topic_id` 同向兜底**，翻页不重不漏。

- **精选回复是话题的附属数据，以话题为单位**——没有 `featured` 之类的开关；凡本页话题 `has_selected_reply=true`，话题对象直接带本专辑对其精选的回复。

- 实现（必须满足，防 N+1）：分页取该专辑 membership → 联 topic 判 Guardian 剔除无权项 → 对本页中 `has_selected_reply=true` 的话题做**一次批量查询** `collection_topic_selected_replies WHERE collection_id=? AND topic_id IN (flag=true 的话题)`，查询内**按 topic 分窗、每个 topic 只取「上限+1」条**、恒 `ORDER BY post_id ASC`（SQL 用 `ROW_NUMBER() OVER (PARTITION BY topic_id ORDER BY post_id)` 封顶；页内 flag 话题数 ≤ `page_size`，也可逐 topic 各取 N+1 再合并）→ 按 topic 分发，多取的那 1 条只作「还有更多」探针、不返回。**内联的必是 `post_id` 最小的几条**（恒 `post_id ASC`）。整页 flag 全 false 则不触发该查询（`has_selected_reply` 在库中的意义即此 O(n) 优化；N+1 探针至多多取一条，绝不回卷全量）。

- 响应每项（收录行）：`added_at`（收录时间）、`note`（公开，仅此处展示）、`topic`（核心话题卡片字段 + `excerpt`，见下）；flag=true 才带 `selected_replies`，另有条件性的 `has_more_selected_replies`（见下）。

- `excerpt`（话题卡片与精选回复均带，**核心生成，不自研截断**）：取帖 `cooked` 经核心 `Post.excerpt` → `PrettyText.excerpt` 出摘要；插件只定长度与选项。**核心给出的摘要是转义后的 HTML 文本**——截断处是实体 `&hellip;` 而非省略号，回复摘要还保留其所引链接的 `<a>` 标签——故返回前一律再经核心 `ExcerptParser.to_plain_text` 落为纯文本（`Topic#plain_text_excerpt` 的同款调用），前端按纯文本插值。话题 excerpt = **首帖（OP）摘要**，与核心列表口径一致（核心在发 / 改首帖时已把该摘要冗余进 `topics.excerpt` 列，读列即可，需自定义长度时再取 OP cooked 现算）；精选回复 excerpt 逐帖现算。长度默认用核心站点设置 `topic_excerpt_maxlength`（默认 220，中文 locale 120）/ `post_excerpt_maxlength`（默认 300，中文 120），卡片要更紧凑可固定更短值；服务端返摘要文本，前端不参与生成。

- **`unlisted`**（`topic` 内的**条件字段**）：仅当该话题**当前已取消公开**（`topics.visible = false`）才返回该键、值恒 `true`；**公开话题一律省略该键**。供前端标记「已取消公开」。该行的可见性受下「收录行的可见性」列表口径约束，普通访问者拿不到 unlisted 行，故该键实际只出现在 **staff / TL4** 的响应里；06 的单行响应用同一卡片形态、规则相同。

- **`users`**（**响应顶层字段**，与 `topics` / `meta` 同级）：本次响应用到的用户，**键为 uid（字符串化的 user id）、值为核心 `BasicUserSerializer` 形态** `{id, username, name, avatar_template}`（`name` 受站点设置 `enable_names` 影响，可能缺席）。行内**一律只带 `user_id` 不带 `username`**——`topic.user_id` = 话题作者，精选回复 `user_id` = 发帖人；前端按 id 来这里取用户名与头像渲染作者区。**某 id 无对应条目 = 该账号已注销**，前端不渲染作者（不输出占位）。只收录本次响应实际引用到的 id，不返回全站用户表。

- `topic` 卡片的 `user_id` = 话题作者（`topics.user_id`，作者已注销时为 `null`）；`category_id` 供前端按核心 `Category.findById` 还原分区徽章（本插件只传 id，不复刻核心话题列表的分区对象）。

- **内联上限**：每个话题随行内联的精选回复至多 `collection_max_selected_replies_per_topic` 条（**站点设置，默认 3**）。精选回复是话题附属数据、**不参与 `page_size`**，热门话题不限会让响应体过大、占满前端版面；故只内联前 N 条，是否还有更多由探针判定（见上）。

- **`has_more_selected_replies`**（每行条件字段，**仅当为 true 才返回该键；false 等同省略、一律不输出**）：true = 该话题精选回复数 > 内联上限，前端据此渲染「查看全部精选」入口，并按需调下方翻页端点。

- **精选回复可见性（内联与翻页端点一致）**：条目按行剔除，分两类——①**软删**（`deleted_at IS NOT NULL`）：预载走裸 `Post.where`，被核心 `Trashable` 默认 scope **先行剔除** → **对所有人都不返回，staff / admin 也不例外**（`can_see_post?` 根本没被调用；与核心话题页不同，那边 staff 带 `.with_deleted` 能看到已删帖）；②**仍在库但访问者不可见**：`hidden`（举报达阈值）、`post_type` 对访问者不可见（whisper 等）及其他，逐条按 `can_see_post?` 判定——**staff / mod 仍可见**（admin / moderator 在 `can_see_post?` 内早退），`hidden` 帖作者本人也可见，其余访问者不返回。**只过滤、不清理行**（见 08）：帖子软删 / 恢复都不动精选行，recover 后精选自动复原；仅帖子**物理销毁**才由 FK `post_id REFERENCES posts(id) ON DELETE CASCADE` 级联清行。

- **已知少报（内联 `has_more_selected_replies` 的尾沿）**：探针先按 `post_id` 每话题取「上限+1」条、再逐条按访问者 `can_see_post?` 过滤——窗口内若混有不可见帖（软删 / hidden / whisper 等）且被滤后可见条数 < 上限，`has_more_selected_replies` 会为 **false**，尽管该话题在窗口外仍有可见精选 → 「查看全部」入口缺失、下方翻页端点不可达。**已知限制、不做自动续查**；影响面小（仅漏报窗口尾部的少数可见条目），如需精确可改为「滤后不足再续取」的算法，或临时调大 `collection_max_selected_replies_per_topic` 降低发生概率。

```jsonc
GET /collections/12/topics.json?page=0&page_size=20

{
    "topics": [
        {
            "added_at": "2026-09-05T08:00:00.000Z",
            "note": "讲得很透，值得回看",
            "topic": {
                "id": 23456,
                "fancy_title": "…",
                "slug": "…",
                "category_id": 5,
                "user_id": 42, // 话题作者；作者已注销时为 null
                "excerpt": "…",
                "created_at": "…",
                "bumped_at": "…",
                "posts_count": 30,
                "unlisted": true // 条件键：仅当该话题已取消公开才出现；公开话题无此键
            },
            "selected_replies": [ // 内联至多 collection_max_selected_replies_per_topic（默认 3）条，post_id 升序
                {
                    "post_id": 999,
                    "post_number": 4, // 前端据此 + 话题 slug/id 构造帖子链接（不经 /p/:id）
                    "user_id": 77, // 发帖人；账号已注销时为 null
                    "created_at": "…",
                    "excerpt": "…"
                }
            ]
            // 本话题精选数未超上限 → has_more_selected_replies 不返回（键省略）。
            // 若实际仍有更多，此处在数组后出现 "has_more_selected_replies": true。
        }
        // …其余条目；没有精选的话题不带 selected_replies 键
    ],
    "users": { // 顶层：本次响应引用到的用户，uid -> BasicUser（见上「响应每项」）
        "42": { "id": 42, "username": "river", "name": "River", "avatar_template": "/user_avatar/…/{size}.png" },
        "77": { "id": 77, "username": "ana", "name": "Ana", "avatar_template": "/user_avatar/…/{size}.png" }
    },
    "meta": {
        "page": 0,
        "page_size": 20,
        "more": true
    }
}
```

- **收录行的可见性 = 分类读权限 + 核心列表口径**：①SQL 层按 `Topic.secured` 收窄（secure 分类等不可见话题）；②**取消公开（unlisted，`topics.visible = false`）**按**核心话题列表的同一判据**处理——仅当访问者 `guardian.can_see_unlisted_topics?`（**staff 或 TL4**）才列出，**不因访问者是该专辑的 owner / 共同维护者而放行**；③行仍逐条过 `can_see_topic?` 兜底（软删 / PM / SQL 收窄不覆盖的其他维度）；④**免打扰（muted）有意不过滤**——核心首页话题流里被 `TopicQuery#remove_muted` 剔除的**免打扰话题** / **免打扰分类**（含间接免打扰）/ **免打扰标签**，本页**一律照列**。免打扰是「别推给我」的分发偏好，只作用于核心的自动话题流；专辑是**人工收录的显式清单**，收录行不因访问者的通知偏好而消失（否则维护者把某分类设为免打扰后，自己收录的话题会从阅读页消失、连带失去内容管理入口）。游客无免打扰概念，不受影响。**unlisted 只决定「上不上榜」，不决定「能不能读」**：持链接者仍可读该话题及其精选回复，与核心 `/t/:id` 一致——故下方精选回复翻页端点**不按 unlisted 过滤**。此类行的 `topic` 带条件键 `unlisted: true`（见上「响应每项」）。

- 本页按访问者可见性**在 SQL 层先行收窄**（secure 分类、已取消公开的话题等不进的窗口不占位）→ 每页返回**连续可见行**：不可见话题只令末段稀疏，不在页中造成孔洞 / 空页；行仍逐条过访问者 Guardian 兜底（PM / 不可见等 SQL 收窄不覆盖的维度）。`meta.total` 与 `topic_count` 均统计**收录总数**（含不可见行、不含已软删 topic）——受限访问者实际可见行可能少于 `meta.total`，按 `more` 一路翻到底可能出现空尾页（前端以「本页行数 < page_size」判终更稳）；staff / TL4 可见全量（含已取消公开的收录行）。

## 2. `GET /collections/:id/topics/:topic_id/selected_replies.json` — 精选回复翻页

查该（专辑，话题）下精选回复的**全量**，供 `has_more_selected_replies=true` 的条目按需翻页。读权限；条目按访问者 `can_see_post?` 过滤，同内联（见本节 1「精选回复可见性」）。

- query：通用分页 `page`（0 基）/ `page_size`（默认 30、上限 50）；排序**固定 `post_id ASC`**（无 `sort`）——与阅读页内联同序，内联片段即本端点第 1 页的前 N 条，翻页不错位、不重复。

- 响应：`selected_replies`（元素与阅读页内联条目同构：`post_id` / `post_number` / `user_id` / `created_at` / `excerpt`）+ **顶层 `users`**（本页引用到的用户，uid -> BasicUser，口径同本节 1）+ `meta: {page, page_size, more}`。此端点**不受** `collection_max_selected_replies_per_topic` 限制，返回全量分页。

## 3. `POST /collections/:id/topics.json` — 收录主题

- body：`{ "topic_id": int, "note"? (≤100) }`

- 行为（单事务）：专辑存在 → 主题存在且 `guardian.can_see_topic?`（不可见按 404，不泄漏存在）→ **主题为私信**（`archetype=private_message`）一律禁收录——对操作者可见的私信（参与者 / staff）按业务规则 **422**（`private_message_topic_not_allowed`）；不可见私信已被上一步 404 挡下 → 已收录则幂等返回 200（不重复计数）→ 新收录：插 membership、`topic_count+=1`、`last_topic_added_at=now`、`has_selected_reply=false`、`collection.updated_at=now`，并**登记订阅通知待发批次**（仅新增时；见 09 的 2）；精选变更不通知。超出 `collection_max_topics_per_collection` → 422。

- 响应：收录成功（新收录与幂等重发同样）**200 + 专辑对象完整形态**（`topic_count` / `last_topic_added_at` / `updated_at` 反映本次写入，便于前端本地对账）。note 长度 ≤100（越界 422；DB 列宽同值，不产生额外 500）。

## 4. `PATCH /collections/:id/topics/:topic_id.json` — 更新单条收录（note + 精选）

把改 note 与精选回复管理合并进这一个端点。body **按需（partial）**：只传要改的字段，缺省字段不动；精选回复用**增量 + 单独删除字段**，不回传整份精选列表——避免大话题每次改动都带完整 body。

```jsonc
PATCH /collections/12/topics/23456.json

{
  "note": "补一句收录理由",   // 选；传值=改，传 null = 清空，缺省 = 不改
  "selected_replies": {
    "add":    [999, 1001],   // 精选这些回复（幂等；post 须属于该 topic）
    "remove": [1000]         // 取消精选（幂等）——单独字段标记删除
  }
}
```

- 字段彼此独立可选，可同请求出现（改 note + 加精选 + 退精选一次搞定）；`selected_replies` 缺省 = 不动精选。

- 同一请求内同一 `post_id` 不得同时出现在 `add` 与 `remove` → 422。

- 行为（单事务）：`add` 后该 `(collection, topic)` 有精选 → `has_selected_reply=true`；`remove` 后已无精选 → `=false`；`collection.updated_at=now`；**不动** `last_topic_added_at`。前置分 add / remove：
  - **add** 目标 post 须存在（未软删）且属于该 topic，否则 404（不泄漏存在）；且**只能精选普通回帖**：主题首帖（`post_number=1` 的 OP）与任何非普通帖（`post_type≠regular`）均不可设为精选回复 → **422**（错误键分别为 `selected_reply_cannot_be_first_post` / `selected_reply_must_be_a_regular_post`）。非普通帖指 posts 表里的系统 / 操作事件条目——closed / pinned / `visible.disabled` 之类经 `Topic#add_small_action` 生成的带 `action_code`、空 raw 的 small_action 帖（`post_type=3`，发帖人多为 system 或操作者，故判断看 `post_type` 而非 user）、whisper（`post_type=4`，非 staff 不可见）与 legacy moderator 帖（`post_type=2`）。判定只发生在 write 端；历史遗留的此类精选行仍可经 remove 撤销（数据库层不清理）；
  - **remove 只删该 `(collection, topic)` 下已存在的精选行，不复查 post 存活 / 归属**——帖子软删后仍可撤销其精选（删行即解除，恢复帖子亦不再复原此精选），remove 无命中行 = 幂等 no-op（不 404）。

- 空 body（`{}`）= 无操作，返回当前收录（200）；重复 add / remove 不存在或已存在的目标均为幂等 no-op。

- 响应：更新后的收录行（与阅读页条目同构：`added_at` / `note` / `topic` / `selected_replies`）+ **顶层 `users`**（该行引用到的用户，uid -> BasicUser，口径同本节 1），供前端本地对账与就地换行。

## 5. `DELETE /collections/:id/topics/:topic_id.json` — 移除收录

- 行为（单事务）：删 membership；同事务删该 `(collection, topic)` 的全部精选回复行；`topic_count` 减（下限 0）；**重算** `last_topic_added_at = max(剩余 created_at)`，空专辑置 `NULL`；`updated_at=now`。本端点**自身不产生通知**，也不改任何通知状态；但它改变了该专辑「最新一次收录」是谁，从而让**由被取消话题开启的那次待发通知**自行失效（见 09 的 2）——取消其它（非最新）话题不影响待发通知。

- 响应：**200 + 专辑对象完整形态**（计数 / 时间已重算）；目标 topic 不在该专辑 → 422。

- 本动作会**连带删除**该 `(collection, topic)` 的全部精选回复行，且行一旦删除不可恢复（见 08）——这是插件里唯一「只取消一条收录、却顺手毁掉一批精选」的写。调用方据此先取本节 7 的计数，再决定是否向用户告警。

## 6. `GET /collections/mine.json` / `subscribed.json`

- `mine`：仅本人；取 `collection_teamworkers.user_id=me` 的全部专辑（每专辑至多一行，无需去重），每项为**列表形态**；此列表里我必为 owner 或共同维护者之一——`owner.id==我` 即 owner，否则 `is_teamworker` 恒 true；`sort` 同全站列表（03 的 3，`created_at|last_topic_added_at|topic_count|subscriber_count`，默认 `last_topic_added_at` desc），分页。

- `subscribed`：仅本人；从 `collection_subscribers` 取集 JOIN collections，每项为**列表形态**（该项 `is_subscribed` 恒 true）；排序与分页同 `mine`——三个列表端点共享同一组 sort 键与默认序。

## 7. `GET /collections/:id/topics/:topic_id/selected_replies/count.json` — 精选回复计数

该（专辑，话题）下精选回复的**行数**，供移除收录（本节 5）前判断这次级联会删掉多少条。权限与守卫同本节 2：插件关 / 匿名未开 → 404；专辑不存在、该 topic 未被本专辑收录、或 topic 对访问者不可见 → 404（不泄漏存在）。

- **无 query**：不是列表端点，无分页 / 排序；**响应恒为 `{ "selected_reply_count": int }`**，不带 `users` 也不带 `meta`。

- **口径 = 全部行数，与访问者可见性无关**：数的是 `collection_topic_selected_replies` 里该 `(collection, topic)` 的行数（一条 `COUNT`，走 `(collection_id, topic_id, post_id)` 索引），**不做 Guardian 过滤**——与本节 1 / 2 的条目过滤**刻意不同**。理由：它回答的是「移除会级联删掉多少行」（删的是全部行，含软删帖、hidden、whisper 的精选行，都不可恢复），是个**总数**而非可见数，与 `topic_count` / `meta.total`「统计收录总数、不统计可见数」同口径。故对同一话题，本端点可能大于本节 2 返回的可见条数。

- 只读、幂等、无副作用，也不改变任何通知状态。
