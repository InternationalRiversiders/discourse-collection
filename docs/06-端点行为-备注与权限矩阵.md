# 端点行为：备注与权限矩阵

## 1. `PUT /collections/:id/topics/:topic_id/note.json` — 改写话题备注（staff）

改写单条收录的 `note`（即 `collection_topics.note` 列），供 staff 修正其判断为**不合规 / 不当**的备注内容；是否不合规由操作者自行判断，系统不做自动判定。与更新单条收录（04 的 4）分工：那边是 owner / 共同维护者改**自己专辑**里的 note + 精选；本端点只改 note、且作用**任意**专辑（含他人专辑、无主专辑）。

- 权限：**admin 恒可、moderator 恒可**——**不随** `collection_moderators_can_manage_collections`（该开关只管专辑级管理操作，见 02 的 1），也不要求操作者是该专辑 owner / 共同维护者；操作者在该专辑无任何身份也可写。无主专辑的备注同样由此修正。

- body：`{ "note": "…" }`——**全量替换**；`"note": null` = 清空。仅此字段，长度 ≤ 100（同收录写入的 note 约束，见 04 的 3 / 04 的 4）。**不能**带精选相关字段（精选 / 取消精选仍 owner / teamworker-only，见 04 的 4）。

- 行为（单事务）：该 `(collection, topic)` 收录必须存在且当前用户能见该 topic（否则 404；staff 通常可见）。只替换 `note`；`collection.updated_at=now`；**不动** `last_topic_added_at` / `topic_count` / `has_selected_reply` 与任何精选行。

- **管理操作审计（见 10）**：**staff 以 staff 身份**改写（即操作者**既非该辑 owner 也非其共同维护者**）才记 `collection_topic_note_change`（旧 note → 新 note；`null` 清空即 旧 → 空）。操作者本就以 owner / 共同维护者身份持有该 note 的改写权（04 的 4）时属常规编辑，**不记**；本端点的写入权限不受影响。

- 响应：更新后的收录行（与 04 的 4 / 阅读页条目同构）+ **顶层 `users`**，供前端本地对账。

## 2. 写权限矩阵

| 操作 | 匿名 | 任意登录 | owner | teamworker | staff（admin；版主按 `collection_moderators_can_manage_collections`） |
| -- | -- | -- | -- | -- | - |
| 读列表 / 详情 / 阅读页 / 单条收录 / 订阅者列表 | 按匿名开关 | ✓ | ✓ | ✓ | ✓ |
| 创建专辑 | ✗ | ✓（须命中 `collection_create_allowed_groups` 且不命中 `collection_create_disallowed_groups`；空允许组 = 禁） | — | — | ✓（须命中，同左；无 staff 豁免） |
| 改名 / 改描述（改元信息） | ✗ | ✗ | ✓（自己的） | ✗ | ✓（任意专辑） |
| 删专辑 | ✗ | ✗ | ✓ | ✗ | ✗（端点不认 staff 身份；须先经 05 的 2.7 自邀接管成为 owner） |
| 收 / 移除主题、精选、取消精选 | ✗ | ✗ | ✓ | ✓ | ✗ |
| 移除维护者 / 本人离队 | ✗ | ✗ | ✓（移除任意共同维护者） | ✓（仅删自己 = 离队） | ✗（无旁路） |
| 发起邀共同维护者（type=0） | ✗ | ✗ | ✓（仅该辑有主时；豁免按发起者） | ✗ | ✗（无旁路） |
| 发起邀成新 owner（type=1） | ✗ | ✗ | ✓（自己的专辑，自主转让；不能选自己） | ✗ | ✓（任意专辑，含无主指定首任；**含自邀接管**，见 05 的 2.7） |
| 撤销邀请 | ✗ | 发起者本人 | ✓（发起者） | — | ✓（该辑**任意**未决邀请；代撤他人发起的记审计，见 05 的 2.2） |
| 该专辑邀请记录（GET `/:id/invites`） | ✗ | ✗ | ✓ | ✗ | ✓（任意专辑） |
| 受邀收件箱（GET `/collections/invites`） | ✗ | ✓（仅本人） | ✓ | ✓ | ✓（受邀人） |
| 接受 / 拒绝邀请 | ✗ | 仅受邀人本人 | ✓（受邀人） | ✓（受邀人） | ✓（受邀人） |
| 改写话题备注（note） | ✗ | ✗ | ✓（经 04 的 4） | ✓（经 04 的 4） | ✓ 任意专辑（经本节 1） |
| 订阅 | ✗ | ✓ | ✓（已自动订阅；退订后可复订） | ✓ | ✓（作为登录用户） |
| 退订 | ✗ | ✓ | ✓（默认已订，退订幂等） | ✓ | ✓（作为登录用户） |

> **换主 / 加维护者一律邀请制**（无「直接生效」行；**staff 对专辑归属与团队无强制旁路**——例外只有两处：**05 的 2.7 staff 自邀接管**只作用于「自己对自己」；**05 的 2.2 管理型 staff 的邀请行撤销权**不触及归属，只删一条未决流程行，且撤销他人发起的记审计）：owner 或 staff 发起 type=1、owner 发起 type=0，受邀人接受才落团队 / 切 owner（见 02 的 4、05 的 2）。矩阵「发起邀成新 owner（type=1）」的 staff 格含**自邀接管**：命中 staff 时选自己 = 当场成为 owner（仍须过 05 的 2.7 的五条校验，含「已是 owner」拦截）。invite 的 `invitee` 不在矩阵按身份判定——受邀收件箱与受理凭「是否该行 invitee」本人判定（任意登录用户皆可能是受邀人）。
>
> **群组准入**（见 01 的 3）：矩阵只按操作者「身份」列判定；对「成为团队一员」的动作（被邀 / 接受），另按**目标 / 受邀人现态群组**设门槛，与操作者身份无关——`action_type=0` 的目标与接受者须命中 `collection_teamworker_allowed_groups`、`action_type=1` 的目标与接受者须命中 `collection_create_allowed_groups`；创建专辑按发起者命中 `collection_create_allowed_groups`（已并入「创建专辑」行）。两条路径**同时受各自的不允许组（`collection_*_disallowed_groups`）约束，且不允许组优先**。**全员按组判定、无 staff 豁免**；准入先于数量上限（豁免角色只豁免上限）。已有专辑 / 团队身份不因之后被移出群组而回收。
>
> owner 可为 null（**无主**）：前端按「无主」渲染。无主专辑的改名 / 改描述由 **staff** 承担（见 05 的 1）、指定首任 owner 由 **staff** 发 type=1 邀请（见 05 的 2.1）；删专辑一行的 ✗ 指**该端点不接受 staff 身份**，不等于 staff 无从清理——**管理型 staff** 可先经自邀接管（05 的 2.7，无主专辑同样成立）成为 owner，再以 owner 身份删除（见 09 的 7）。
>
> **例外**：上表「改写话题备注（note）」一行的 staff 权限是 **admin 与 moderator 均恒可**、不经 `collection_moderators_can_manage_collections`——改写备注只是修正单条收录的内容，不等于专辑「管理操作」（改名 / 改描述 / 发起换主邀请），故版主默认即具备（见 02 的 2、本节 1）。
