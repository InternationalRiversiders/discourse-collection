# 通用约定

## 1. URL 层级

engine 直接 `mount at: "/"`（对齐官方 rewind / automation / workflows 的做法），资源路由为**顶层路径**，不经插件名前缀——插件名与资源名撞词（discourse-collection × collections），不把插件名垫进 URL。路由总表（02）所列路径即最终 URL。唯一例外是「话题页整合」，它加在核心端点 `/t/:id.json` 上。

## 2. 鉴权三层门

由 `before_action` 串联，先判总开关，再判匿名，写操作再判登录与权限矩阵：

| 门 | 规则 |
| -- | -- |
| `collection_enabled` 关闭 | 所有插件端点 → 404，前端无入口（整插件隐身） |
| 匿名访问 | `collection_allow_anonymous=false`（默认）→ 读接口对匿名 404；`=true` → 匿名可读、仍不可写 |
| 写操作 | 一律需登录，再按「写权限矩阵」（06 的 2）判 403 |

## 3. 群组准入

四个 `group_list` 站点设置构成写操作的前置门槛，按能力分两组、每组各一条允许组与一条不允许组：

- **允许组**：`collection_create_allowed_groups` 与 `collection_teamworker_allowed_groups`，默认均含 `trust_level_1` 自动组；留空 = 该能力对所有人关闭（与 core 同类 `*_allowed_groups` 一致：空 map → 无人命中）。

- **不允许组**：`collection_create_disallowed_groups` 与 `collection_teamworker_disallowed_groups`，默认均空；留空 = 不拒绝任何人。

**不允许组优先**：同时命中允许组与不允许组者一律被拒。**全员一律按群组成员身份判定，无 staff 豁免**（admin / moderator 也不例外）。成员资格**只在操作发生那一刻判定**，已有专辑 / 团队关系不因用户之后被移出群组而回收或作废。此门槛**先于**各上限 / 豁免判断执行；`collection_unlimited_*_role` 豁免角色**只豁免数量上限、不豁免准入组**。判定归属：

- **可拥有专辑**：命中 `collection_create_allowed_groups` 且不命中 `collection_create_disallowed_groups` 者，才可**创建专辑**（03 的 2）、被邀为**新 owner**（05 的 2.1，`action_type=1` 的目标）、接受 type=1 邀请（05 的 2.5）。

- **可成为共同维护者**：命中 `collection_teamworker_allowed_groups` 且不命中 `collection_teamworker_disallowed_groups` 者，才可被邀为**共同维护者**（05 的 2.1，`action_type=0` 的目标）、接受 type=0 邀请（05 的 2.5）。

**创建入口不在前端重述本节判定**：`current_user`（页面预载与 `/session/current.json`）携带布尔 `can_create_collection`，值即上面「可拥有专辑」那条判定；为 false 时列表页的创建按钮与帖子操作栏弹窗的创建入口都不渲染。该布尔只决定入口是否展示，创建端点仍按本节独立判定。

## 4. 错误体

统一 `{ "errors": ["..."] }` + 状态码，靠核心 action 兜底：`Discourse::NotFound`（404）、`Discourse::InvalidAccess`（403）、`Discourse::NotLoggedIn`（403）；业务校验直接 422。

## 5. 读安全

凡返回 topic / post，一律过访问者 Guardian（`can_see_topic?`），无权项**在服务端剔除**后再返回（见 CLAUDE.md 的 schema 硬规则）。冗余计数列（`topic_count` 等）不受此影响——它统计的是收录总数，不是可见数。

## 6. 分页

query `page`（0 基，默认 0）+ `page_size`（默认 30，上限 50）。响应附 `meta: {page, page_size, more}`。`more` = 是否还有下一页；`total` 口径各端点见详述：列表类按命中集合给，阅读页（04 的 1）例外按收录总数给（不可见 topic 也计入）。

## 7. 排序

query `sort` + `order`（`asc|desc`）。各端点默认见详述；非法 `sort` → 400。

## 8. 时间

一律 UTC ISO 8601。时间列是 PostgreSQL `TIMESTAMP`（naive、无时区），本身**不做时区转换**——靠约定写入 UTC，经 Rails（UTC 读写）序列化为带 `Z` 的 ISO 8601 输出；写入端 Service 必须自律只写 UTC。**前端展示时按用户时区自行格式化**（与 Discourse 核心时间一致）。

`last_topic_added_at` 可空：`NULL` = 从未收录过，排序时视为最旧（空专辑排在 `desc` 末尾、不占榜）；新增收录时写 now，移除后重算见 04 的 5。
