# 端点行为：专辑

## 1. 专辑对象的两种形态

下文凡返回专辑对象即二取其一，不逐端点复述全字段：

- **完整形态**（创建响应、详情）：专辑全部列——`id` / `name` / `description` / `topic_count` / `created_at` / `updated_at` / `last_topic_added_at`（可 null = 从未收录）——加 `owner`（用户对象，可 null = 无主）、`teamworkers`（**不含 owner** 的共同维护者数组；元素为用户对象，同 `owner` 字段）、`subscriber_count`、`is_subscribed`。

- **列表形态**（全站列表、mine / subscribed）：全部列 + `owner` + `teamworker_count` + `subscriber_count` + `is_teamworker` + `is_subscribed`。`teamworker_count` = 共同维护者人数（`teamworkers` 数组的压缩，前端无空间展示全部维护者）；因列表不逐人带出维护者，新增访问者相关的 `is_teamworker`（当前用户是否共同维护者，见下）。

- 角色判定分两档：**owner 判定**两形态都凭 `owner.id == 当前用户`；**共同维护者判定**完整形态比对 `teamworkers[].id`、列表形态读 `is_teamworker`（不重复输出：完整形态给数组、不给布尔）。`is_teamworker` / `is_subscribed` 都按当前访问者算：登录者查 `collection_teamworkers`（`is_owner=false` 行）/ `collection_subscribers`，匿名（开 `collection_allow_anonymous`）恒 `false`；owner 恒不算共同维护者（`is_teamworker` 恒 false），但已**自动订阅**自身专辑（`is_subscribed` 默认 true，退订后 false）。

- `subscriber_count` 读存储列 `collections.subscribers_count`，恒 = 该专辑订阅行数 − 当前 owner 行（有则减）：**owner 是唯一「订阅但不计入」的人**（自动订阅落行，见 02 的 5）。

## 2. `POST /collections.json` — 创建

- body 字段与长度约束：

- `name`（必，去首尾空白后）：长度 ∈ [`collection_name_min_length`, `collection_name_max_length`]（默认 3–20，**含边界**）；名称非空，下限不因空串放宽。

- `description`（选，默认 `""`）：长度 ≤ `collection_description_max_length`（默认 200）。

- 越界 → 422；DB 列宽（name `VARCHAR(100)` / description `VARCHAR(1000)`）与设置上限一致，恒不构成额外拦截。

- 行为：owner = 当前用户——同一事务落一条该用户 `is_owner=true` 的 teamworker 行（owner 即团队一员，DB 保证每专辑至多一个 owner），**并落一条该用户的订阅行（自动订阅，见 02 的 5）**；按该用户为 owner 的专辑数（即其 `is_owner=true` 行）≥ `collection_max_collections_per_user`（默认 20）→ 422；`created_at=updated_at=now`、`last_topic_added_at=NULL`（空专辑）、`subscribers_count=0`（owner 行不计入）。

- 上限豁免：命中 `collection_unlimited_collections_role` 的当前用户不受上述上限约束，可继续创建。该设置单选 `nobody|admin|staff`，默认 `nobody`（= 无豁免、全员限 20）。

- **准入（见 01 的 3）**：当前用户须命中 `collection_create_allowed_groups`（留空 = 无人可创建）且**不**命中 `collection_create_disallowed_groups`（默认空 = 不拒绝任何人；同时命中两条时以不允许组为准），否则 **403**（`InvalidAccess`）。此判断先于上面每用户上限——`collection_unlimited_*_role` 只豁免数量上限、**不豁免**准入组。

- 响应：专辑对象**完整形态**（字段见本节 1）；新建即落 owner 行 + owner 订阅行，故 `owner` = 当前用户、`teamworkers=[]`（owner 不计入数组）、`subscriber_count=0`（owner 行不计入）、`is_subscribed=true`（已自动订阅；owner 可退订）。

## 3. `GET /collections.json` — 专辑列表

- query：`username`（选，缺省全站；给定则返回**该用户创建或维护的专辑**——凡 `collection_teamworkers` 中该用户有行即命中，`is_owner=true` 的 owner 行与普通维护行一视同仁）、`sort` ∈ `created_at|last_topic_added_at|topic_count|subscriber_count`（**默认 `last_topic_added_at`**）、`order`（默认 `desc`）、分页。`subscriber_count` 直接读存储列 `collections.subscribers_count`（无需聚合）；`last_topic_added_at` 的 NULL 视为最旧、`desc` 时排末尾。

- 匹配口径同 mine（04 的 6）：按 `username → user_id` join `collection_teamworkers.user_id` 过滤，只是 mine 限本人、这里按任意用户。一用户在一专辑至多一行（owner 与共同维护身份互斥），命中不重复；该用户不存在或无可命中专辑 → 空列表。

- 响应每项：专辑对象**列表形态**（字段见本节 1；`owner` 可 null → 前端显示「无主」）。

- `teamworker_count` 用聚合查询带出、`subscriber_count` 读存储列 `subscribers_count`；访问者布尔 `is_teamworker`（查当前用户在本页各专辑的 `is_owner=false` 行）与 `is_subscribed`（查订阅）各一次批量 join，登录才查、匿名恒 false——均避免逐行 N+1。

## 4. `GET /collections/:id.json` — 专辑详情

- 返回：专辑对象**完整形态**（字段见本节 1；`owner` 可 null = 无主，`teamworkers` 不含 owner）。

- 前端据 `owner.id` / `teamworkers[].id` 与当前用户 id 比对判定自己是 owner 还是共同维护者；另据客户端 `currentUser.admin` / `currentUser.moderator` + `siteSettings.collection_moderators_can_manage_collections` 判定是否命中 staff（admin 恒命中；moderator 按设置）。命中 owner 才渲染改名 / 改描述（05 的 1）入口与「加维护者」邀请入口；命中 owner（自主转让）或 staff（任意专辑）渲染「换主」邀请入口（见 05 的 2.1）；该专辑 owner 渲染「移除维护者」入口。`is_subscribed` 按当前访问者算，渲染订阅按钮。

- 不含收录内容（那是阅读页，04 的 1）。
