# 话题页整合（核心端点 `/t/:id.json`）

反查不另设插件端点，直接扩展核心 `TopicViewSerializer`（`add_to_serializer`）。话题页整合含**两级最小反查**——话题级（该主题被哪些专辑**收录**，顶层 `collections`）与 post 级（该回复被哪些专辑**精选**，注入被精选的 post）。两级都只给定位信息，note / 精选内容详情一律点进专辑才看。

## 1. 话题级反查（顶层 `collections`）

与 `post_stream` 平级注入 `collections`，仅当该主题被 ≥1 个专辑收录时出现；**每项最小，只给 `id` + `name`**（不显示 note / 精选 / owner；某条收录的 `note` 需单读，见 04 的 8）。该数组同时充当 post 级反查的**名字解析表**：精选某 post 的专辑必为该话题的收录专辑（精选前置是收录，见 04 的 4）→ ⊆ 顶层 `collections`，故 post 层只需 id、名字与跳转链接一律经顶层解析，零重复注入。

## 2. post 级反查（`selected_by_collection_ids`）

`post_stream.posts` 中被 ≥1 个专辑精选的 post，注入 `selected_by_collection_ids`（**该 post 被精选于的专辑 id 数组；键仅当该 post 有精选时出现，无则省略**）。只给 id、不带名字与任何精选内容；反查以话题为单位、命中量由该话题的精选数决定，**全给、不分页、不受** `collection_max_selected_replies_per_topic`（那是专辑阅读页内联展示上限，与此无关，见 04 的 1）。

```jsonc
{
  "id": 23456,
  "post_stream": {
    "posts": [
      { "id": 900, "post_number": 4, "..." : "…" },
      { "id": 901, "post_number": 9, "..." : "…",
        "selected_by_collection_ids": [12, 30] }   // 仅被精选的 post 带该键
    ]
  },
  "collections": [
    { "id": 12, "name": "XX 阅读清单" },   // 顶层 = 收录该话题的专辑；名字/链接在此解析
    { "id": 30, "name": "YY 摘录" }
  ]
}
```

## 3. 行为约束

- include 条件：`collection_enabled` 关闭 → 两级都不注入。话题级：该主题无收录 → `collections` 键不出现；post 级：该 post 无精选 → `selected_by_collection_ids` 键不出现（大多数话题、绝大多数 post 零输出）。

- 查询：话题级一次 `collection_topics (topic_id, collection_id)` 索引取 membership → JOIN collections。post 级按话题级这批 collection id 收窄后一次取齐该话题的精选行（`WHERE collection_id IN (…) AND topic_id = ?`，走 `(collection_id, topic_id)` 索引），按 `post_id` 分组；同话题所有被精选 post 一次算齐、序列化各 post 时命中组内结果——**不做逐帖查询**。反查结果与访问者无关，无需 Guardian 过滤（能打开 `/t/:id` 即话题可见；专辑恒为公共）。

- **per-post 只给「精选反查」id、不给「精选内容」**：excerpt、note 等精选回复内容只在专辑阅读页（04 的 1）与翻页端点（04 的 2）返回，post 层不做内容注入——避免为一条不展示的信息引入逐帖 payload。
